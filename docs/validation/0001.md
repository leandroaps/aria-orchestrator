## What broke

### B1. `aria` was not a command (fixed here)

The skills and workflows run `aria …` as a bare command, and Claude Code puts
a plugin's `bin/` on the Bash `PATH`. But `bin/` held only `aria.mjs`, so no
executable named `aria` existed. The Lead found the CLI in the plugin cache
and ran `node <cache>/bin/aria.mjs` instead.

Fix: `bin/aria`, a shell shim that runs `aria.mjs` next to it. Still to
confirm on a reinstall: that `aria` now resolves inside a session.

### B2. The tool guard read a heredoc's body as shell (fixed here)

The `test` agent first wrote its file with `/bin/cat > test/slugify.test.mjs <<'EOF' …`.
The guard parsed the JavaScript inside as shell: each `=>` became a redirect
to `{`, outside the territory, and the write was denied. The agent retried
with the Write tool. That was a false positive, inherited from bernardo.

Fix: the write-target reading skips heredoc bodies, unless the heredoc's
line feeds an interpreter (`sh`, `bash`, `node`, `python`, `xargs` and
others, directly or through a pipe), whose body runs.

While testing the fix, a gap that fails open showed up: `node < file` and
`node <<EOF` read a program on stdin, but the guard took the `<` token for
the script's name and let them through. Fixed: a redirect from stdin makes
`node` opaque, as `node -` and `… | node` already were.

### B3. No Workflow tool in the session

The session offered no `Workflow` tool, so the Lead followed the manual
protocol of the `orchestrate` skill, as the skill says to on an observed
missing capability. The protocol worked, but the three workflows did not run
live. The cause was not checked: workflows can be disabled by settings, by
`CLAUDE_CODE_DISABLE_WORKFLOWS`, or need enabling on some plans.

### B4. The run never leaves `running`

After every task was accepted, `aria status` showed `running`, with the
final review as the next step. Already noted in P6: no command moves a run
to `ready_for_review`. Nothing blocked; it is a missing state change.

### Not the plugin

- The sandbox's shell had a broken `cat` alias. That is the local
  environment, not the plugin.
- `ß`, `ø` and `ł` become hyphens in `slugify` (they do not decompose under
  NFD). That is the spec's scope, and its non-goals allow it.
